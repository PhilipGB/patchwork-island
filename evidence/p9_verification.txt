P9 runtime assertions specifically include:
- new game opens the character chooser; the real Boy, Girl and Cancel buttons
- Boy and Girl each start the correct appearance and are saved on disk
- Continue restores either chosen appearance after returning to the title
- cancelling a fresh chooser or a replacement chooser leaves the old save intact
- opening the real clothes shop and pressing the actual Sunny Day Buy button
- wallet text changes from 10 to 2 after the 8-coin purchase
- every outfit has an enabled Preview control, including unaffordable outfits
- focusing/pressing Preview updates the name, price, wallet and Not enough coins
- previewing changes neither the wallet, ownership nor equipped outfit
- unaffordable and already-owned action buttons are disabled
- the domain refuses insufficient, duplicate and unowned outfit operations
- a failed clothes save shows an inline error and still applies the look in memory
- the next successful clothes save clears that previous error message
- Save Now while driving, Continue restores Girl + Sunny Day + 2 coins
- New Game reset after reload returns to Boy + Everyday + 0 owned outfits + 0 coins
- recovery seed with Girl/Berry restores ownership and appearance after reload

Save schema tests
-----------------
- A schema 1 save loads and migrates to schema 2 in memory.
- Wallet, active mission, completions, tutorials, pickups, inventory, player
  position and settings all survive the migration and the schema 2 rewrite.
- Missing character fields default to Boy + Everyday + no purchases.
- The pre-migration schema 1 file remains as save.json.bak.
- Schema 3 and 99 loads return UnsupportedNewer and leave every byte untouched.
- An ordinary save over schema 3/99 is refused before writing; no backup or
  newer-vN copy is created by the refused write.
- Explicit replacement still preserves a newer-v99 copy before writing schema 2.

Save compatibility
------------------
Schema 2 is current. Schema 1 is migrated with all progress preserved.
Schema 3+ is unsupported and is never loaded, downgraded, discarded or
overwritten automatically. Only an explicitly confirmed New Game may replace
it, after preserving a newer-vN copy.
